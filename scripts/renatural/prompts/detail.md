## 条目五拍（叙事节拍，不是编号标题——标题形态自由，五拍义务在场即可）

1. **何时需要它**：真实场景开场（维护遭遇 / 用户抱怨 / 报错信息），禁「对了一半」钩子。
2. **最小用法**：能跑的最小片段 + 配套 example 指引；不贴完整工程（禁全码）。
3. **机制内部**：这一控件区别于族内兄弟的机制（信号时序 / 状态模型 / 事件路径 / 属性联动），断言三锚；**H2 标题必须是机制句**（如「两态下调 setCheckState 为什么不生效」），这是五拍防模板化的硬规。
4. **坑贴机制**：坑长在机制小节里，三要素齐；断言必须与所贴代码互证——基线冷读在 qcheckbox 篇抓到的双杀（L38 / L261 两处断言互相矛盾且全错，经 `qt_src/qt6.9.1/qtbase/src/widgets/widgets/qcheckbox.cpp:217-228` 实证）就是「条目断言不落锚 + 代码与论证脱节」的现成反面教材，改写该篇时先按实证改断言（内容债已登记 `renatural/state/coldread-baseline.md` §4）。
5. **何时不用它**：仅存在**真实取舍关系**时指向替代控件（QTextEdit 结尾指 QPlainTextEdit）；族内独苗或无真实取舍就退回普通导航句，禁硬凑。

## 检查点与检查点 A 铁律

每篇 1–2 个内联在机制小节后；形态 A/B/C 定义与折叠格式见 README §2。**A 类行为断言（「注释掉这行第 5 段输出消失」）必须先 `cmake -B build && cmake --build build` 实测再写**，检查点带 example 相对路径与命令；对不上 = 不写，不将就。

## 防五拍模板化

五拍是义务不是格式：拍与拍可合段、可换序（认知顺序优先）；机制句标题、走法轮换、echo_lint 零命中、术语按 glossary——四道锁都在，谁批产模板谁被拦。连续条目篇写作时特别自查：相邻两篇的开场句式、第②拍引导句、收尾句不得同构。

## `--chief` 族长变体（11/12/13/14/15/16 六篇）

在五拍之外加三件：
1. **族级导览** 3–5 句（开篇后）：您现在在哪、本族管什么、成员怎么分工（谁管什么、什么场景选谁）——与 index.md 分组一致，零文件迁移。
2. **检查点 ≥2 且 ≥1 个 A**：族级检查点 A 挂真实 example（族长是族内检查点的锚点）。
3. **成员分工一览**：以链接清单落正文（内容描述式），承诺只写本族已有篇，不预写不存在的成员篇。
族长篇的走法指派优先「历史演进 / 抛技术问题」（族级开场更稳）。
