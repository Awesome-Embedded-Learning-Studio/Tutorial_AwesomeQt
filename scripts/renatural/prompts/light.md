# 家族 prompt：light（轻改篇）v0.9-draft

> 适用：W6（05-other-modules 25 篇，两阶段 mechanical→editorial）与 W8（00-env 3 篇 + 8 个 index.md）。写手开工前必读：`scripts/renatural/prompts/README.md` §2 共用红线（生效项见下——light 不是免检通道，只是工序不同）。
> light 的纪律恰恰最严：改得少，所以每一行改动都必须说得清为什么。

## W6 · 05-other-modules：两阶段工序

**阶段一 mechanical（纯脚手架剥离，diff 形状机器校验）**：只许删三类行——━━ 类分隔条 / 「链接已验证」日期戳 / 仪式行（「让我们开始吧」「大功告成」类收尾）。删除行必须逐行匹配三类 regex（invariants --diff 校验 diff 形状），**阶段一不碰任何其他字符**。阶段一产物单独 commit（`renat/w6-mech/<slug>`），与阶段二分开审。

**阶段二 editorial（换声 + 升格）**：在阶段一之上走五方向义务——内联坑升格（散落的「注意」段升为三要素坑）、补检查点（1–2 个，模块包已装则 A，否则 B/C）、开场走法指派、导航块、description 关键词化。共用红线全量生效：humanizer 归零、弯引号、单字「先」禁、echo 零命中。旧文句子与 theme 同等对待（不复用），但保真对账范围以阶段一之后的文本为基线。

## W8 · 00-env 3 篇 + 8 个 index

- **env 篇**：隐性测验显性化——旧文的「试试看」段升为正式检查点（**B/C 形态**，00-env 无配套 example，W-EX 裁决 3：不为此建示例工程）；02-cmake 的检查点挂 08-file-io 的 example（裁决指定归属）。五方向里「机制」方向对 env 篇表现为「操作因果」——每步操作写清它防止什么坑。
- **index 部首段**（8 个 index.md 各 150–250 字）：四要素 = 您现在在哪 / 本部解决什么 / 会用到前面哪几篇 / 读完能做到什么。**承诺必须从本部正文反向提炼**（写完逐篇对照「正文真讲了」），每部收尾门对照兑现。部首之外 index 的改动限于进度行（与账本同源，`ledger.py` 生成注入，不手写正文进度）。

## 通用约束（两波共用）

- 机器红线全量生效（humanizer / 「」/ 套话 / 「先」/ 报数标题 / 前缀——存量 index 标题若带编号，W8 一并去）。
- invariants 对账照跑；W6 阶段一的删行若涉及代码块 / 链接计数变化，逐项登记账本增删（分隔条 / 日期戳 / 仪式行三类不计入不变量，其余计）。
- 走查四道不减：light 的走查重点是「删多了吗 / 升格升对了吗」，批内最险篇全读照旧。

## 交付

阶段一：diff + 三类 regex 逐行匹配说明。阶段二 / W8：同 theme（整文件新稿 + 修订说明）；index 篇额外交四要素对照表（承诺 ↔ 正文落点）。
