1. **来路**：这篇解决什么真实问题、读者带着什么困惑来。用 preflight 指派的走法开场（抛技术问题 / 维护遭遇倒放 / 报错信息起手 / 最小实验起手 / 历史演进起手），与相邻篇不同走法。禁「说实话我第一次」编造亲历、禁报菜名路线图、禁假想对话。

3. **机制**：概念按认知顺序登场——先给读者已见过的现象，再起名字，再拆内部。每条行为断言落三锚之一（example 实测 / qt_src 文件:行号 / doc.qt.io 标版本）；机制前提要点破，不许指望读者拿工程直觉补（基线教训：信号发射 = 同步直调这种前提必须写出来）。**检查点穿插在此方向**，每篇 1–2 个：A 动手实验（默认，挂真实 example，行为断言先实测）/ B 预测题 / C 找错题；`>` 块引用 + 粗体「检查点：」，答案 `<details>` 折叠。**不设练习栏目**（D4）。
4. **翻车**：坑穿插在机制行文里（不设栏目），每坑三要素齐——场景 / 具体崩法 / 从根因长出的解法；只写真坑。H2 标题写机制本身或观点句（禁编号、禁「类名——比喻」），判据：读完正文回看标题，标题承诺的事正文真干了。
5. **收尾**：官方文档真实链接（标 Qt 版本）+ 篇尾导航块四行（§2 共用红线）。禁仪式收尾（「让我们……吧」/ 展望句）。
