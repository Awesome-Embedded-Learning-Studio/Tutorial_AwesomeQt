- 用途：① 写手与走查的密度取舍依据；② 冷读 panel 的画像卡唯一真相源——后续冷读必须逐字使用本文件 §2 画像卡，保证与基线可比。

## 2. 画像卡（冷读用，逐字冻结）

P1/P2/P3 三卡为基线冷读实测用卡，原样保留；P4 为补卡（基线未上 panel，理由见 §4）。

**P1**：你是嵌入式/C++ 工程师，写了十年单片机和 Linux 驱动，C++ 熟练但没做过 GUI，Qt 是第一次碰。中断、生命周期、内存所有权这些你门儿清；信号槽、事件循环、控件体系对你全新。你讨厌啰嗦，只想知道机制本质和坑。

**P2**：你是计算机专业大三学生，学过 C++ 课和数据结构，会写课程作业级别的程序，没写过真实项目。遇到没讲清的步骤会卡住，需要动手实验来建立理解，喜欢有检查点验证自己。

**P3**：你是桌面软件老手，Qt4/Qt5 时代写过界面，后来转去做别的了，现在回流学 Qt6。旧 API 你有肌肉记忆，最关心 Qt6 变了什么、老习惯哪里会踩雷；啰嗦的入门讲解会让你跳读。

**P4**：你是非科班转型者，从测试 / 运维 / 其他行业转来学编程，C++ 是跟着入门书自学的，指针和内存还在似懂非懂之间。你不怕慢，怕的是文中默认你已知的东西没人告诉你去哪补。

## 3. 冷读执行规则（含基线教训，M1 起生效）

- panel 组成：P1/P2/P3 各一个全新上下文 agent（独立上下文 = 天然冷读）；P4 不进 panel——10% 权重的密度决策已定（转诊出去），进 panel 只会稀释信号；P4 由写手与走查按「转诊义务」承担。
- 盲读规则（沿用基线）：只许读目标篇作答；答不出老实写「答不出」不许编；每题自报置信（有把握/纯猜）；答完报 stuck_points 与 voice_impression。
- 判卷三分制（依基线饱和教训定死）：每题分**消化复述**（自己的话把因果链说对）/ **照抄复述**（背出文章原句但追问因果就空）/ **空心对**（结论对但因果链文章没给、靠读者直觉补的）。只有消化复述计入通过；空心对必须在问题单里点名「文章没给，读者补的」。
- 出题规则：core 题中至少 1 题「为什么型」——要求从文中代码 / 机制推出因果，防复读得分（基线满分正是复读可得）。
- 主判据（问答之外）：读者自发问题数（卡点 / 发现矛盾 / 空心点）目标趋零；与断言三锚核查联动——读者报的矛盾点直接进保真走查复核。

## 4. 基线校准输入（2026-09-28，M1 校准时以此为本）

- **P1 会补偿**：基线中 P1 拿 ISR 防重入直觉补上了文章没讲清的「信号发射 = 同步直调」前提——P1 的满分不可作为文章合格证据，判卷必须区分「读者补的」与「文章给的」。写手侧结论：P1 类比是入场券不是替代品，机制前提仍要点破。
- **P2 卡点全在文内不在基础**：基线卡点全部来自文内矛盾与断言无锚，无一来自基础欠缺——「P2 密度兜底」策略有效，权重暂不动。
- **P3 判卷质量最高且内容上有增量需求**：主动区分复述层次、自行核代码；最想要 Qt5→Qt6 增量对照——改版在迁移处给一句增量即可满足，不开专栏。
- **P4 观察项**（基线无数据，M1 校准时补）：检查转诊链接密度是否够 P4 活下去——以走查抽验代替 panel。
